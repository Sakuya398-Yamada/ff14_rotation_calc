# Phase 1 補足: 作業中の別の Issue との重なり

`phases/01-issue-analysis.md` 手順 3 から、親 Issue があるか、「## 関連Issue」に Open Issue があるか、本文に触るファイルのパスがあるときに読む。同じ箇所を触る Issue が作業中なら、並行セッションが同じ仕組みを二重に実装してコンフリクトするので、着手前に見る。以下の「手順 2」は `phases/01-issue-analysis.md` の手順 2（関連 PR の確認）を指す。

## 兄弟 Issue との重なり（親 Issue があるか、「## 関連Issue」に Open Issue がある場合）

同じ親の sub-issue を、まず番号・タイトル・状態だけで一覧する（`gh api "repos/{owner}/{repo}/issues/<親番号>/sub_issues?per_page=100" --jq '.[] | [.number, .title, .state] | @tsv'`。sub-issue は親 1 件あたり 100 件までなので 1 回で全件取れる。`--paginate` はクラウドセッションで 2 ページ目に止まるので使わない。`.claude/skills/issue-start/pitfalls-cloud.md`「クラウドセッションでは `gh api --paginate` が 2 ページ目で止まる」）。`issue_read`（method: `get_sub_issues`）は sub-issue ごとに本文とメタデータを全部返すので、sub-issue の多い親ではツール出力の上限を超える。`gh` が無くて `get_sub_issues` を使うなら、出力が退避されたファイルを丸読みせず、番号・タイトル・状態だけを抜き出す。本文末尾の `親Issue: #N` だけで親を書いた兄弟（sub-issue の階層の上限で親を付けられなかったものなど）は、この一覧に出ない。Open Issue を本文ごと一覧で取り、同じ `親Issue: #<親番号>` を持つものも兄弟に入れる（番号のすぐ後ろに数字が続くもの、`#80` に対する `#800` などは除く。取り方は `.claude/skills/issue-start/SKILL.md`「起票フロー（共通）」手順 1）。本文の「## 関連Issue」に挙がった Open Issue も、兄弟と同じく扱う。そのうえで、同じファイル・型・関数・共通データ・共通ロジックに触れそうな兄弟 Issue だけを `issue_read`（method: `get`）で個別に読み、本文を照合する。重なる兄弟があれば `search_pull_requests`（query と PR の数え方は手順 2 と同じで、番号は兄弟 Issue のもの）と `git ls-remote --heads origin '*/<兄弟の番号>-*'`、兄弟 Issue のコメントの「## 着手」の印（クラウドの割り当てブランチはブランチ名に番号が入らない。「## 着手（取り下げ）」と、セッション URL がこのセッション自身の印は除く。後者は前の Issue を中断して移ってきた残りで、`phases/02-branch-setup.md`「クラウドセッションの場合」手順 4 で取り下げる）で、その兄弟に作業ブランチやオープン PR が既にあるかを見る。印があれば、印のブランチがリモートにあるかも `git ls-remote --heads origin <ブランチ名>` で見て、その結果とセッション URL を確認に添える（ブランチが無くても、まだ push 前の作業中のことがある。手順 2 と同じ）。親 Issue が Open で、同じファイル・型・関数・共通データに触れそうなら、親も同じく作業中かを見る（PR の query・ブランチ名・印は親の番号のもの）。スコープ外の起票で作られた子は親の作業中に近くの箇所で見つかったものが多く、`依存:` を書かない子でも親の PR と同じファイルを触ることがある。重なりがあるときは、共通部分をどの Issue で実装し、他方はそのマージ後に取り込むのかを着手前にユーザーへ確認する。Issue 本文に重なりが書かれていなくても確認する

## 同じファイルを触る、兄弟でも関連Issue でもない Issue

本文に触るファイルのパス（「補足」の該当箇所など）があれば、そのファイル名で Open Issue の本文を文字列で探す（取り方は `.claude/skills/issue-start/SKILL.md`「起票フロー（共通）」手順 1 の、Open Issue を本文ごと一覧で取って `contains` で絞るもの）。当たった Issue（この Issue と、上で見た兄弟・関連Issue を除く）は、兄弟と同じく作業ブランチ・オープン PR・着手の印を見る。作業中のものがあれば、本文から触る節を読み、同じ節を触りそうなら着手前にユーザーに確認する（節が違えば機械的にマージできることが多く、意味の食い違いは Phase 7 で、取り込む前に `main` で入った変更を読むときにも拾える）
